# Icons

An icon is a small picture that stands for a command, a place or a state. This file is about when a screen has icons, what an icon is for, and how to tell a good set from a bad one. It is not about how to draw them. If the design system has no icons, this file says when their lack is no loss.

## What an icon is for

Pictures are older than writing and weaker than it: to explain a thing with no words, you need an image that each person knows, and for most things on a screen there is none. A database, a link and a share have no picture that explains them.

- **An icon does not explain; it is recognised.** A person finds a known picture faster than a known word. Thus an icon speeds the way to a command that the person already knows, as a face speeds the way to a chat.
- **An icon also saves space**, and it needs no translation.
- **The text explains, the icon is found.** The two work well together. A new or rare command has a text label; an icon with no text is only for a command that people use each day or know from each product (close, search, the cart).
- **An icon with no text in the place of a label is a puzzle** for each person who did not learn it. Many "known" icons are known only to people of one platform, and people often take one for a different one (a pencil is read as "edit" where the platform means "new").
- Signs in public places are a different case: there a picture must work for a person of each language, and it shows a real thing (a plane, a cup, stairs). Even there, a thing with no clear picture (a lift) gets a word.

## The main job: to differ

- **In a set, each icon differs from the others by its shape, and by its color where the design system permits.** The person finds an icon by its outline and its place, at the edge of their view, with no reading.
- **The test: look at the whole toolbar with the eyes half closed.** If the wanted icon is still found, the set is good. If the icons run into one grey mass, it is not. Judge icons in their bar, never one by one.
- **No puzzle icons.** Do not build a meaning from small parts: a sheet with a gear and a plus for "add a line of service", a cylinder with two people and a lock. All such icons look the same, and the person has to decode them. A cart is enough for "add to the cart"; the plus on it is noise.
- **Remove the part that repeats.** If each icon is "a sheet with a thing in its corner" or "a thing in a frame", only the thing stays. Equal frames, circles and backgrounds around each icon make them one shape; this is the common part outside the brackets (see [Lists](./lists.md)).
- **A family by style, not by shape.** Icons of one set share the weight of the line, the angle of view, the way of drawing. They do not share an outline.
- **The place of an icon does not change**, and the icons are in groups by meaning (see [Layout](./layout.md)). People learn the place together with the picture. A picture that people know keeps its place also when its object is long gone from the world.
- When the system forces one shape on each icon (app icons), the picture inside and its color carry all the difference.

## Where icons go

- **Not on each item.** In a menu or a list, icons on the few important items help to find them. An icon on each item is a column of grey marks that helps to find none.
- **Never a bar of icons with no labels as the narrow form of a menu.** A side bar that drops its text at a smaller width has no meaning left. Keep the labels and let the bar scroll, or use the form for a narrow width from [Navigation](./navigation.md).
- **Two or three choices that the person must make fast are words**, not icons: buttons with "End and answer", "Hold and answer", "Decline" are read faster than three pictures made of circles.
- An icon in a corner of a panel is read as a control; see [Controls](./controls.md).

## A state or a command

An icon on a button can mean the state now or the command that a press gives. A crossed microphone: is the microphone off, or does a press turn it off?

- **Decide one meaning for the whole product**, and use it for each related control. Do not cross out one of two neighbors and leave the other.
- **Add a word.** Only a text label settles it: "Microphone is off" as a state, "Turn off" as a command. See "A state is written as a state" in [Labels](./labels.md).
- A filled and an empty form of the same icon is one more sign that must agree with the others; see "The state of a control" in [Controls](./controls.md).

## What a picture also says

- **A picture carries meanings that you did not intend.** A heart for "favourites" on a flat for one night, a political sign for a language, a figure of one sex for "a person". Check each picture in the context of this product, and prefer a neutral one (a star, a simple figure).
- **A state can be the same icon, dimmed**: on is colored, off is grey. The person reads "is there a colored thing in the corner" with no look at the picture.
- Decoration of icons for a holiday is done by each product; do it only when it is light and does not make the icon harder to find.

## With the design system

- Use the icon set of the design system, and only icons that it has. Do not mix sets, and do not draw a near copy of a missing icon.
- If the set has no icon for a thing, use a text label. A label alone is a complete control.
- If the design system has no icons at all, the screen has text labels, and loses only speed for daily users. Tell the user where an icon would help most: a toolbar of commands that are used many times a day.

## What to draw

- Icons with text labels, or with no labels only on the few commands that each person knows.
- A toolbar whose icons differ in outline and are in groups.
- Icons on a few items of a menu, not on each.
- A word at each icon that can mean a state or a command.
